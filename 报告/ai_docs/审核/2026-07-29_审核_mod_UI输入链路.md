# mod_UI 输入链路完整审核

> 生成日期: 2026-07-29 | 类型: 审核 | 状态: 已确认

## 背景

本次审核针对 `mod_UI` 输入链路进行完整检查，重点关注多行输入、受控组件状态回写、剪贴板和文件导入、HTTP/HTTPS 归档 URL 识别、前端统计与后端解析的一致性。此前包列表输入框存在只能输入一行的问题，修复过程中发现多个模块存在相同的即时清洗模式或协议判断残留。

## 问题分析

### 现状

1. 包列表由 `WorkspaceView` 的受控 `<textarea>` 展示，实际状态由 `App.tsx` 的 `input` 管理。
2. 手动输入、剪贴板粘贴、文件导入、历史记录回填、去重、排序和清理均通过 `acceptInputValue` 或 `onInputChange` 进入同一状态链。
3. 后端 `parse_inputs_filtered` 已支持按行解析，并允许 HTTP/HTTPS 安装归档 URL。
4. 前端部分辅助函数仍使用只匹配 `https://` 的正则，导致 HTTP 内网归档被错误归类。

### 根因

1. `App.tsx` 曾对所有输入统一调用 `trimTrailingBlankLines`，手动按 Enter 产生的末尾换行被立即删除，受控组件随后回写为单行。
2. `SettingsView.tsx` 的自定义排除正则编辑框在每次 `onChange` 时执行 `trim().filter(Boolean)`，末尾空行无法保留，连续编辑多条规则时体验异常。
3. `utils.ts` 的输入规范化、输入分类、去重、重复统计和智能建议仍使用 `^https://` 判断，未同步前端对本地 HTTP 归档 URL 的支持。

## 核心发现

1. 后端逐行解析逻辑本身没有导致包列表只能输入一行；主要问题发生在前端受控状态回写层。
2. 仅修改 `WorkspaceView` 的 Enter 事件不足以解决问题，必须保证 `App.tsx` 接收层不裁剪手动输入的末尾换行。
3. HTTP/HTTPS 支持必须在输入统计、去重、规范化提取和智能建议等所有前端辅助路径保持一致。
4. 配置类多行编辑应保留用户编辑中的空行，保存或提交时再进行结构化清洗，不能在每次键入时破坏编辑状态。
